# 🚨 First thing I'd check: Render environment variable

Your code looks for:

```ts
process.env.TURNSTILE_SECRET
```

or:

```ts
process.env.CLOUDFLARE_TURNSTILE_SECRET_KEY
```

So your Render backend needs **one of those exact names**.

I'd standardize it to:

```env
TURNSTILE_SECRET_KEY=your_cloudflare_secret
```

and change the code to:

```ts
const secretKey = process.env.TURNSTILE_SECRET_KEY;
```

Don't keep three possible names. It makes debugging harder.

In Render:

**Backend Service → Environment → Environment Variables**

Add:

```text
Key:
TURNSTILE_SECRET_KEY

Value:
<your Cloudflare Turnstile secret key>
```

Then **redeploy**.

# 🚨 Second issue: your fallback is dangerous

This:

```ts
return process.env.NODE_ENV !== 'production';
```

is not something I'd keep.

It means:

```text
Development → Siteverify fails → LOGIN ALLOWED 😬
Production → Siteverify fails → LOGIN DENIED
```

For security middleware, we want verification failure to **fail closed**.

Change it to:

```ts
catch (err) {
  console.error('[TURNSTILE SITEVERIFY EXCEPTION]:', err);
  return false;
}
```

And also explicitly check the secret:

```ts
const secretKey = process.env.TURNSTILE_SECRET_KEY;

if (!secretKey) {
  console.error('[TURNSTILE] TURNSTILE_SECRET_KEY is not configured');
  return false;
}
```

# 🚨 Third: check the actual Cloudflare response

This is the most important diagnostic.

You already have:

```ts
console.log(`[TURNSTILE SITEVERIFY RESULT]:`, JSON.stringify(data));
```

Go to:

**Render → your backend → Logs**

Then attempt login once.

We want to see something like:

```json
{
  "success": true,
  "hostname": "www.alpha-cut.com"
}
```

If instead you see:

```json
{
  "success": false,
  "error-codes": [...]
}
```

**the error code is the answer.**

For example, if you see something related to:

```text
invalid-input-secret
```

→ wrong/missing Render secret.

If:

```text
invalid-input-response
```

→ token isn't valid/reaching Cloudflare correctly.

If:

```text
timeout-or-duplicate
```

→ you're reusing an expired/consumed token.

# ⚠️ There's another thing I noticed

Your frontend sends:

```json

  "turnstileToken": "...",
  "cf-turnstile-response": "..."
```

You don't need both.

Your backend already supports:

```ts
req.body?.['cf-turnstile-response'] || req.body?.turnstileToken
```

I'd simplify the frontend to:

```ts
body: JSON.stringify({
  email,
  password,
  turnstileToken,

```

and backend:

```ts
const token = req.body?.turnstileToken;
```

Cleaner.

Alternatively, use Cloudflare's conventional name everywhere:

```text
cf-turnstile-response
```

Either is fine. **Just use one.**

I'd personally use:

```text
turnstileToken
```

between your frontend and API, because it's explicit and easy to understand.

# One more architectural improvement

Eventually I'd move this:

```ts
verifyTurnstileToken(req)
```

out of `auth.controller.ts`.

Something like:

```text
backend/src/
│
├── controllers/
│   └── auth.controller.ts
│
├── middleware/
│   └── turnstile.middleware.ts

├── services/

└── routes/

```

Then:

```ts

  '/login',
  validateRequest(loginSchema),
  verifyTurnstile,
  login
);
```

That makes the controller responsible for authentication and the middleware responsible for bot protection.

But **don't refactor everything yet**. First let's get the current implementation working.
