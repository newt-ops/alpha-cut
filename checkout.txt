This document defines the production standards for the Alpha Cut web ecosystem before the first official public deployment.

The goal is not simply to make the website "work."

The goal is to make Alpha Cut:

* Professional
* Search-engine friendly
* Accessible
* Fast
* Secure
* Maintainable
* Well documented
* Legally presentable
* Easy to deploy
* Easy to expand
* Consistent with the Alpha Cut brand

# 3. Production Domain Rules

The canonical public website should be:

```text
https://alpha-cut.com
```

Decide whether:

```text
https://www.alpha-cut.com
```

will redirect permanently to:

```text
https://alpha-cut.com
```

Recommended:

```text
www.alpha-cut.com
        ↓
301/308 redirect
        ↓
alpha-cut.com
```

This avoids having two versions of the same website indexed by search engines.

Do not allow both versions to behave as independent websites.

# 26. Do Not Index Private Areas

The following should generally **not be publicly indexed**:

```text
/admin
/dashboard
/auth
/login
/api
```

However, don't rely only on `robots.txt` for security.

Robots.txt is **not an access-control mechanism**.

Private pages must still require authentication.

For protected pages, consider:

```html
<meta name="robots" content="noindex, nofollow" />
```

and enforce authorization at the backend.

* Focus states
* Color contrast
* Labels
* Semantic HTML
* Screen readers
* Motion
* Forms
* Error messages
* Touch targets

# 33. Keyboard Navigation

Everything interactive must be accessible without a mouse.

Test:

```text
Tab
Shift + Tab
Enter
Space
Escape
Arrow keys where appropriate
```

Users should be able to:

* Open navigation
* Navigate links
* Submit forms
* Close modals
* Operate controls

# 34. Focus States

Never remove focus outlines without replacing them with an equally visible focus style.

Bad:

```css
outline: none;
```

Better:

```css
:focus-visible {
  outline: 2px solid ...;
  outline-offset: 2px;
}
```

Use the actual Alpha Cut design system rather than blindly copying a color.

---

# 35. Color Contrast

Alpha Cut's visual design should maintain sufficient contrast.

Pay particular attention to:

* Body text
* Buttons
* Placeholder text
* Navigation
* Footer
* Links
* Text over images

Do not sacrifice readability for aesthetic minimalism.

# 36. Motion Accessibility

Because Alpha Cut is a creative/video brand, the website may contain animations.

Respect:

```css
prefers-reduced-motion
```

Example:

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms;
    animation-iteration-count: 1;
    transition-duration: 0.01ms;
    scroll-behavior: auto;
  }
}
```

The exact implementation can be adapted to the animation library.

# 41. Core Web Vitals

Pay attention to:

### LCP

Largest Contentful Paint.

The main hero content should load quickly.

### INP

Interaction to Next Paint.

Buttons and interactions should feel responsive.

### CLS

Cumulative Layout Shift.

Reserve space for:

* Images
* Videos
* Fonts
* Dynamic components

Avoid elements suddenly jumping around during loading.

# 83. The Core Principle

Alpha Cut should be built with a simple rule:

> **Build only what we need now, but structure it so we don't have to rebuild everything later.**

We don't need to launch with:

* A huge client portal
* Complex analytics
* Dozens of email types
* A massive admin system
* Every possible automation

But the architecture should already support them.

The first public website should be **fast, polished, accessible, searchable, secure, legally presentable, and professionally documented.**

That gives Alpha Cut a proper foundation for the larger agency platform we're building.
